# 中国市场每日增量更新

在 Qlib 仓库根目录执行：

```bash
conda activate qlib
python scripts/update_cn_data.py
```

默认更新 `~/.qlib/qlib_data/cn_data`。需要代理时：

```bash
python scripts/update_cn_data.py --proxy http://192.168.164.106:16688
```

先验证、不替换正式数据：

```bash
python scripts/update_cn_data.py --dry-run
```

## 数据如何更新

数据来自 `chenditc/investment_data` 在 DoltHub 上公开的同一个数据库。
脚本使用只读 SQL HTTP 接口，无需 Tushare token、Docker，也不需要先克隆整个数据库。
每次固定一个 Dolt commit，通过 `AS OF` 查询，避免读取过程中数据版本变化。
接口每页最多返回 1000 行，脚本自动分页，不会只更新前 1000 只股票。

1. 获取最新行情日期及交易日历，确认与本地历史日历一致。
2. 获取本地日历末日之后的行情；首次出现的股票补取其完整历史。
3. 校验已有股票最后一个有效交易日的原始价格、成交量、成交额和复权价。
4. 沿用本地复权尺度转换新增行情。停牌空档按完整交易日历补 NaN，避免日期错位。
5. 在完整数据副本上调用 Qlib 的 `DumpDataUpdate`，逐项验证新增字段及旧二进制前缀。
6. 更新五个指数股票池和未来交易日历。指数只查询衔接所需的最近成分快照。
7. 验证通过后替换正式目录，仅保留本次更新前的最新备份，删除同级旧备份。

无需再手工执行 `scripts/dump_bin.py dump_update`。新增 CSV 保存在每次运行的工作目录中，
不使用先前那个空的 `normalized_daily_data` 目录。

## 输出和恢复

- 正式数据：`~/.qlib/qlib_data/cn_data`。
- 更新前备份：同级目录下的 `cn_data.backup-日期-时间`。
- 工作目录：同级目录下的 `.cn-update-随机字符`，其中 `normalized/` 保存本次归一化 CSV。
- 数据来源记录：正式数据目录中的 `incremental_update.json`，包含 Dolt commit 和最新日期。

成功更新后自动清理同级目录下符合 `cn_data.backup-YYYYMMDD-HHMMSS` 格式的旧备份，
仅保留本次更新前的备份。更新失败、无新增数据或使用 `--dry-run` 时不清理备份。
符号链接不清理；若旧备份删除失败，会提示原因，已完成的数据更新不受影响。
工作目录仍需自行清理；运行中的工作目录不可删除。
恢复时，先停止读取行情的程序，将当前目录移到其他名称，再把所需备份改名为 `cn_data`。
更新完成后，重启已有的 Python/Jupyter 内核，以免继续使用旧的日历缓存。

## 使用边界

- 这是新增行情的追加更新，不会自动重写过去的历史修订，也不处理合并换股等公司行为。
- 若衔接日历史行情变化，脚本会停止并保留诊断目录，需核对来源后决定是否全量重建。
- 若作者尚未发布新行情，脚本会提示无新增数据；相同日期重复运行不会重复追加。
- 每个新增交易日至少要求 `min(1000, 本地股票数)` 条源数据，这是缺数的基本检查，不能代替全市场质量审计。
- 正式更新时应暂停回测和行情读取；目录替换需要两次重命名。
- 每日收盘后、作者数据更新完成再运行即可。这里不自动安装定时任务。

## 验证

```bash
python -m unittest discover -s tests -p test_update_cn_data.py -v
```

测试涵盖复权与股数尺度、停牌空档、新股、历史修订拒绝、旧二进制不变、指数成分恢复、
无更新时的幂等行为、公开接口分页和快照固定，以及目录替换失败时恢复原数据。
